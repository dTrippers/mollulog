# 학생부 public 데이터 계약

학생부(`/students`)는 로그인 여부와 관계없이 BAQL의 공개 학생 카탈로그만
사용합니다. 사용자 DB, 소유 여부, 현재 레벨, 인연 레벨은 학생부 목록의
요청·필터·정렬·표시 정보에 포함하지 않습니다.

## 전용 projection

공용 `getAllStudents` query를 확장하지 않고 `student-directory.ts`의 전용
query를 사용합니다. 목록 기본 필드와 다음 compact 필드만 요청합니다.

```graphql
students {
  uid name familyName altNames school initialTier order
  attackType defenseType position tacticRole birthday role equipments released
  catalog {
    profile { age schoolYear height }
    terrainAdaptations { street outdoor indoor }
  }
}
```

프로필 전문, 무기 설명, 성장 배열, 전체 스탯 배열은 요청하지 않습니다.
나이·학년·키는 숫자로 변환하지 않고 BAQL의 문자열을 그대로 보존합니다.
카탈로그나 개별 공개값이 없으면 사용자에게 `정보 없음`을 표시합니다.
현재 자료 기준 compact projection은 약 135KB raw, 14.9KB gzip이며, 표시
정보를 바꿀 때 재요청하지 않도록 한 번에 함께 받습니다.

## 학생부 동작 계약

- 검색은 이름·성·별칭을 대상으로 합니다.
- 학교·공격 타입·방어 타입·클래스·전술 역할·포지션·장비 슬롯·초기 성급
  필터는 필터 그룹 사이 AND, 같은 필터 안의 값 사이 OR로 조합합니다.
- 장비는 1·2·3번 슬롯을 별도 필터로 제공합니다.
- 기본 필터와 정렬 아래의 `더 보기`를 열면 학교·장비·초기 성급 필터가
  표시됩니다. 추가 필터가 저장되어 있으면 처음부터 펼쳐지며, `n개 적용`으로
  현재 선택된 추가 필터 값의 수를 알립니다.
- 장비 1·2·3번은 각 행에서 세 가지 선택지를 가로로 제공하고, 초기 성급은
  1·2·3성 세 가지를 노란 별 아이콘과 숫자로 제공합니다.
- 정렬은 최신순·과거순·이름순·초기 성급순을 제공하며, 동률에는 order와
  UID를 사용해 안정적인 순서를 유지합니다.
- 그룹은 그룹 없음·학교·공격 타입·방어 타입·클래스·포지션 중 하나만
  선택합니다. 학교는 한글 이름순, 나머지는 기존 도메인 옵션 순서입니다.
- 카드 표시 정보는 없음 또는 다음 항목 중 하나를 선택하며 기본값은 없음입니다.
  없음을 선택하면 카드 하단 label을 렌더링하지 않습니다. 공격·방어·클래스·
  전술 역할·포지션·장비 1/2/3·초기 성급·나이·학년·키·시가지/야외·실내 적성을
  선택할 수 있습니다.
- 초기 성급은 검은 카드 label strip 안에 노란 별 아이콘과 숫자로 표시하며,
  접근성 이름과 title에는 `초기 성급 3성`처럼 개념과 값을 함께 넣습니다.
- 시가지·야외·실내 적성은 등급 문자를 카드에 직접 표시하지 않고 기존 등급
  아이콘을 사용하며, 접근성 이름과 title에는 `시가지 적성 S`처럼 지형과
  등급을 함께 넣습니다. 값이 없으면 `정보 없음`을 표시합니다.
- 공격·방어 타입은 검은 label strip 안의 텍스트와 의미 색상으로 표시하며,
  색상만으로 타입을 구분하지 않습니다.
- 필터 해제는 검색과 필터만 초기화하고 정렬·그룹·표시 정보는 유지합니다.

## 한국어 label

학교에는 카드 비교에 맞춘 짧은 한국어 label을 사용합니다. 장비 슬롯도
`모자`, `장갑`, `신발`, `가방`, `배지`, `헤어핀`, `부적`, `시계`, `목걸이`의
명시적 매핑을 사용합니다. 매핑되지 않은 내부 code를 사용자 화면에
노출하지 않습니다.

## BAQL 비교 및 채택 범위

이번 구현에서 채택한 값은 현재 MolluLog와 BAQL에 공통으로 존재하는 학생
identity·전투 분류·학교·포지션·장비 배열 및 compact catalog 값입니다.
`weaponType`, 최초 획득 유형, 현재 획득 가능 상태와 계산 스탯은 계약이
정의되지 않아 UI 선택지에서 제외했습니다.

다음 BAQL/baql-sync 후속 계약이 마련되면 별도 변경으로 검토합니다.

1. `CharacterExcel.weapon_type`의 명시적 enum 매핑과 GraphQL `weaponType`
2. 학생·지역별 `acquisitionType`
3. 획득 유형과 분리된 `availabilityStatus`
4. `archive`, `encore`, `recollect`를 혼합하지 않는 정규화
5. 근거·지역·기준 시각을 포함한 availability source
6. 모집 기록이 없는 학생을 위한 명시적 `unknown` 또는 검토된 override

현재 구현은 `archiveAt`이나 모집 이력으로 획득 유형·가용 상태를 추론하지
않습니다.
